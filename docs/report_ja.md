# 適応型ドローン巡回点検

2026年10月16日 / A〜Jの10地点・物理飛行と1倍速の説明動画

## 1. 目的と構成

同じ学習済みAIが、地点の優先度と有向移動コストの変化に応じて巡回順序を変更し、実際のドローンが全地点へ飛行して点検する。上位はMaskablePPO、下位はGenesis/RSL-RLの4モータPPOである。提供ノートブックの飛行制御・録画を継承し、実到達と連続滞在の後に再計画する構成へ拡張した。

今回の承認済み仕様は specs/2026-10-14-realtime-demo-video/spec.md。先行する経路最適化と全地点表示・安定飛行のマージ済みコードを起点とし、ローカル保存済み素材で編集した。追加学習・追加撮影は行っていない。

## 2. 学習・一般評価の結果と限界

ルーティング採用seedは42、10行動・324要素の観測である。3シード42/43/44で各100,352 PPOステップ、学習用厳密状態による初期化を経て、検証用集合でモデルを固定した。推論時に厳密オラクルや教師へのフォールバックはない。

各モデルに同じ静的100例・動的50例を使用した。採用seed42の静的平均目的コスト164.995、平均AI/厳密解比1.030、最悪比1.136。全300静的・150動的エピソードが完了し、無効行動は0件だった。採用seedの動的50例では48例に更新を適用し、選択変更5例、改善2例である。デモの成功を、一般条件で常に最適な方策という主張に読み替えない。

目的関数は、α×移動コスト＋β×優先度を重みとした名目完了時刻のペナルティ（小さいほど良い）である。α=β=1、名目速度1 m/s、サービス0.50秒、帰還なし。有向辺倍率は移動コストに適用し、名目移動時間や物理速度・電力とは区別する。優先度は重要度であり、訪問順そのものではない。

## 3. 実点検の受入

到達は半径0.20 m以内・実速度0.30 m/s以下の連続0.20秒、点検は同条件で合計0.50秒滞在して確定する。逸脱で滞在をやり直し、reset、落下、非有限値、目標不一致、通信異常、timeoutは成功に数えない。追加学習後の model_1300.pt を固定して使用した。

固定3シード×通常・緊急・コスト変化の9試行はすべて成功し、90/90地点を点検した。通常17.82秒、緊急17.23秒、コスト変化17.23秒。滞在中最大残差0.199755 m、最大速度0.299781 m/s、全legの最大傾斜33.527度、最低高度0.804635 m。失敗した開発試行と元モデルも保持する。固定初期条件の決定論的試験で、シード間の軌跡は一致した。

## 4. 環境変化と実際の応答

地点Bを3.96秒で点検した直後、緊急シナリオは地点Cの優先度2.660866→5、コスト変化シナリオは有向辺B→Aのみ倍率1→5を更新した。更新なしの予測はA→E→G→H→I→J→F→D→C。更新後の予測はC→D→F→J→I→H→G→E→Aとなり、実際の次選択もAからCへ変わった。イベントから次の実点検完了までの映像を含め、飛行区間を省略していない。

同じ境界・更新後条件で旧順序と新順序を比較した名目総コストの改善は、緊急25.219823、コスト変化7.035441。後者の移動成分は7.8→5.4。これらは論理モデル上の比較であり、物理飛行時間やエネルギーが減ったという測定ではない。予測は凍結条件の仮想順序であり、将来の実飛行を確定した線ではない。

## 5. 近い低優先度地点を先に回る比較

実物理判断 cost_shift_seed_1 / decision-1、3.96秒の同じsnapshotで比較した。近いL＝地点Cは優先度2.660866、計画距離0.600 m、実位置から0.611003 m。遠い高優先度H＝地点Hは優先度2.693373、計画距離1.200 m、実位置から1.181392 mである。

Lを先にする条件付き最適解はC→D→F→J→I→H→G→E→A、Q*(L)=149.096595（移動5.4＋完了時刻143.696595）。Hを先にする条件付き最適解はH→I→J→F→D→C→A→E→G、Q*(H)=168.795996（移動6.6＋完了時刻162.195996）。差は19.699401である。J*=149.096595を残り全順序の厳密DPで確認し、同じ凍結方策のAI予測も149.096595だった。

この判断は「現在の条件を固定した残り巡回」における最適な次の一手であり、この例ではAIの残り巡回全体も最適だった。一般の判断では次の一手と全体の最適性を別々に判定し、未証明なら最適性未確認と表示する。入力と出力のコスト分析であり、AIの内部思考を読んだという説明ではない。

## 6. 1倍速動画と独立検証

出力先は outputs/realtime_20261016_v2/。full_normal.mp4、full_emergency.mp4、full_cost_shift.mp4 は全10地点の飛行を自然尺で保持する。demo_full.mp4 と submission.mp4 は3本の完全な飛行と独立した静止説明カードを収録する。提出用も省略なしで、96.30秒のうち52.30秒（54.31%）が実飛行である。カード中に架空の時計を進めず、飛行を引き伸ばさない。

元rawは50fpsの定期撮影に境界の追加撮影が重なり、符号化PTSが実物理時刻からずれていた。元raw・frames.csv・物理ログは sources/ に完全コピーした。raw/ の新動画は同stepの最新event_seqを採用し、追加撮影を消した理由と元frame番号を記録する。VFRのPTSを物理時刻に合わせ、強制撮影された端数の終端も保持する。最終フレームはmission-endの状態を表し、コーデック用の1物理step分の末尾packetを追加飛行として扱わない。

編集版は1920×1080、H.264、30fps。Genesis画面は元の1280×720のまま配置し、全地点の色・数値、実位置、目標と点検状態を重ねる。出力は単位傾斜の時間写像で元の実フレームを選び、最後の1出力フレームは実mission-endを表示する。各シナリオの尺誤差と終端の表示ずれは最大1出力フレーム以内とする。

独立checkerは元のphysics step・実timestep・元rawと出力の実PTSを読み直す。全デコード、フレーム数、各飛行フレームの画素参照情報、日本語の時計・点検数・目標、元カメラ由来の機体拡大像を照合する。イベント提示時刻・末尾coverage・完全な巡回順序の成分コストも再計算する。宣言されたplayback_rateだけを信じず、実測のずれを記録する。合否・ハッシュは verification.json と manifest.json、実フレームの目視結果は引き継ぎ記録に保存する。

2026年10月17日、ユーザーから「目視して動画はOKでした」と確認を受領した。これを人手確認の完了として記録し、独立した機械照合・静止画確認と合わせて今回仕様の受入をPASSとした。改善案は別spec／PRで扱う。
