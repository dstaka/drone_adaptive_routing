## Batched simulation, profiling and effective isolation

The reported peak GPU utilization of 22% is a user observation, not a measured throughput ceiling or a prediction of 4.5x acceleration. NVIDIA utilization is the fraction of a sample period with executing GPU kernels. The current code explicitly builds `n_envs=1`, uses one active size bank, reads many tensors to CPU and writes per-step JSON. Determine the bottleneck from actual profiling.

Keep **one GPU-owning job** at a time; allow many environments inside it. Do not run competing PPO jobs or add a GPU/rental. Prefer real Genesis batched tensors on the device. A Python loop over independent single-environment scenes is a fallback to measure, not a claim of GPU vectorization. General Genesis documentation is guidance; all native-ball/geometry/property/reset capabilities must be confirmed on the installed pinned 1.4.3 source and real runtime.
